# 两分钟项目演示脚本

这份脚本用于录制作品集演示，也可以直接作为面试中的项目讲解提纲。演示只使用合成运单和本地开发环境，不展示密钥、客户数据、私人录音或本机绝对路径。

## 演示目标

两分钟内证明四件事：

1. 这是会调用业务工具并执行任务的 Agent，不是普通问答机器人；
2. STT 和 LLM 的概率输出不能直接产生高风险业务副作用；
3. 查询与改约都受跨回合确认、精确匹配、并发检查和回读约束；
4. 项目有自动化、模拟、后端集成和真人语音的分层证据。

## 录制前检查

- 使用仓库提供的合成夹具或专用本地测试订单，禁止使用真实客户信息；
- 关闭会暴露 `.env*`、API key、账号、通知和本机用户名的窗口；
- 先运行 `uv sync --locked --dev`、`uv run python -m pytest` 和 `uv run ruff check .`；
- 查询和时段展示可以直接演示；改约写入只能对隔离的合成订单执行，并且需要录制者在当前会话中再次明确授权；
- 如果不执行写入，就演示“准备后取消”，并明确说明没有把取消演成成功提交。

## 建议演示输入

请使用本地合成夹具实际存在的号码，不要在公开脚本中写入真实运单。推荐对话结构：

1. “帮我查一下这个运单，我一个数字一个数字念。”
2. 口述合成号码，等待 Agent 逐位复述；
3. 下一条消息说“号码正确”；
4. “有哪些可以改约的派送时间？”
5. “先选第二个时段。”
6. 未获得写入授权时说“先不要改了”；获得授权并使用隔离夹具时，下一条消息再明确确认提交；
7. 在一段较长回复中说“你别说了”，观察回复停止。

## 失败时怎么展示

演示不应通过剪辑掩盖业务失败。可以保留一次安全失败，并解释门禁如何工作：

- 号码不完整：拒绝请求后端，继续允许语音重说或键盘输入；
- 号码纠错：覆盖候选并重新复述，旧候选不能继续授权查询；
- 订单版本变化：拒绝提交并要求重新查询；
- 写入请求超时：先回读最终状态，不盲目重试；
- 模型或语音 provider 暂时不可用：说明当前是外部依赖故障，不把未执行的任务报告成成功。
